## 3. Gemini Live API (voice) is a working, production-shaped asset — the strongest reuse target for "talking agents" (high confidence)

Cloudforce's `backend/agents/live/` is a complete WebSocket bridge to Gemini's Live (real-time audio) API, built for "talk to your lecture" voice tutoring. TechnoMile's I6 read this and dismissed it as "out of scope" for a Black Hat (text/research) product; it is core, not peripheral, for the Arena's talking subject agents and voice coaching.

- `/Users/balla/Desktop/satvik/Summer Internship/cloudforce/backend/agents/live/session_manager.py` (full file read, 398 lines): `MarginaliaLiveSession` — opens `genai.Client(api_key=...).aio.live.connect(...)`, streams PCM16 audio in (`send_realtime_input`), relays audio-out chunks and input/output transcription text over the WebSocket as JSON frames, wires one retrieval tool (`lecture_lookup`) and one UI tool (`ui_set_grounded`) as Gemini Live function declarations, binds ContextVars (`run_id_ctx`, `lecture_id_ctx`, `user_id_ctx`) so cost receipts inside tool dispatch FK correctly, and persists transcript+citations+cost to Postgres in one idempotent UPDATE on disconnect (insert-before-connect, FK-safe).
- `/Users/balla/Desktop/satvik/Summer Internship/cloudforce/backend/agents/live/safety.py` (full file read): `LiveCostMeter` computes real-time USD cost from audio-in/audio-out/video-frame token estimates at Vertex Live native-audio pricing, and a `safety_loop` ticks every 2 s to hard-close the session on max-duration, cost-cap, or idle timeout — each with a distinct WebSocket close code. This is a directly reusable per-session budget-governor pattern for BKO-5's "consistent... response budgets" and EVL-5's cost/latency reporting.
- `/Users/balla/Desktop/satvik/Summer Internship/cloudforce/backend/agents/live/system_prompt.py` — single permissive system prompt set at connect time (the Live SDK cannot mutate `system_instruction` mid-session); runtime mode-switching (strict vs general grounding) is smuggled through tool-response fields instead. This is a real constraint the Arena will hit if it wants a Live-voice subject agent whose private profile or evidence-release state changes mid-interview (SCN-10): the pattern to copy is "push state changes through tool outputs, not system-prompt mutation."

**Contradiction with the owner's locked constraint.** `session_manager.py:130-135` comments explicitly: "`gemini-3.1-flash-live-preview` is published on AI Studio (`generativelanguage.googleapis.com`) but NOT on Vertex's `location=global` for non-allowlisted projects, which 1008-NOT_FOUNDs the connect. Use the AI Studio client for the Live socket; the rest of the pipeline keeps using Vertex." The code therefore uses `genai.Client(api_key=cfg.gemini_api_key)` (AI Studio / Gemini Developer API), not Vertex, for the one component that does real-time voice. The owner's hard gate is "Gemini models via Vertex AI only" (BRIEF.md line 11). If the Arena wants a Live-voice layer, this is a direct conflict that needs resolving (check current Vertex Live allowlist status, since this was written in 2026-05 and Vertex Live availability may have changed) before any voice feature is built.

- Confidence: high for the code's behavior and the AI-Studio-vs-Vertex split (read in full, comment is explicit and the code matches it); medium for whether this conflict still exists today (model/API availability changes fast; not independently re-verified against current Vertex docs in this route — flagged in BRIEF.md as something to prefer 2025-2026 sources on, which R7/R8 routes should check).

## 4. TTS (multi-speaker, Vertex, grounded, gated) — directly reusable for a "subject speaks" feature (high confidence)

`/Users/balla/Desktop/satvik/Summer Internship/cloudforce/backend/agents/audio_overview.py` (full file, 1022 lines) implements a complete, Vertex-only (not AI-Studio) two-voice TTS pipeline: `generate_script()` calls `gemini-3.1-flash-lite` (Vertex, `location=global`) for a structured `AudioScript` (turns with `voice: "A"|"B"`, grounding rules tying every line to a prior summary, a private checklist), then `synthesize_audio()` calls `gemini-2.5-flash-tts` (Vertex, `location=global`) with `MultiSpeakerVoiceConfig` to produce raw PCM, which is encoded to MP3 via `pydub`/ffmpeg (with a documented tempfile workaround for an ffmpeg-8.x seekback bug), uploaded to GCS, and served via V4 signed URL minted through SA self-impersonation (no JSON key). The whole thing runs inside an ADK `LoopAgent` with the same generate -> Sentinel -> Council -> gate shape as the rest of cloudforce's artifact pipeline (covered generically in I6), with a dedicated `sentinel_audio` and `_CouncilAudioGate`.

- Confidence: high (full file read; the Vertex-only TTS path has no AI-Studio fallback comment, unlike the Live path above — this one is clean against the owner's constraint).
- Source: `/Users/balla/Desktop/satvik/Summer Internship/cloudforce/backend/agents/audio_overview.py:1-1022` — read 2026-10-08.
- Implication: this is the lowest-risk voice feature for the Arena — it is Vertex-only already, and the generate -> grounded-gate -> synthesize shape matches AST-3/SUB-2 (a subject's spoken answer must still be grounded in the private profile, gated the same way text artifacts are). Could directly back a "subject speaks its answer" feature without violating the Vertex-only constraint, unlike the Live bridge in section 3.

- **Picker** (`PetPicker.tsx`, path confirmed, not fully read this route) — lets a profile owner choose a pet/style combination; directly reusable for letting an investigator pick their coach's avatar, or distinguishing assistant-candidate vs subject-candidate visually in the bake-off UI.

No `rive`, `lottie`, `framer-motion`/`motion`, `three`, or `pixi` dependency is used for the pets specifically (grep for those package names in `recruiter-frontend/package.json` and `frontend/package.json` returned the files but not pet-specific imports; I5 already documents that `motion`/`framer-motion` and `three` exist in these repos for other surfaces — marketing hero shaders, 3D knowledge graph — confirmed there, not re-litigated here). The pets are plain SVG + CSS + a hand-rolled spring/rAF loop (`../spring`, `../raf` modules, not read in this route).
