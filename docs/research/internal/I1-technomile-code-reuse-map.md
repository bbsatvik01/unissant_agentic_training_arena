## 2. Agent layer — competitor role-play as the closest analog to simulated subjects

TechnoMile's S9 "swarm" (`services/run/src/bh_run/tail/swarm.py:1-21,135-524`) role-plays each approved rival company from ONLY that rival's accepted evidence claims, with no tools and no visibility into other rivals' data. This is structurally the best available analog to SUB-1..SUB-8 (private profile, permitted knowledge, concealment-within-rules):

- **Persona slice** (`roleplay.py:128-139`, `persona_slice`): each persona sees only claims naming it, capped at `SLICE_MAX=30` — directly maps to SCN-8 (private subject packet: "what the subject actually knows").
- **Cite-or-drop** (`roleplay.py:146-169`, `supported`/`keep_points`): every point must cite evidence codes (`E1, E2...`) from the persona's own slice; any point citing an uncited code, or restating a figure/magnitude its evidence doesn't state, is **dropped silently**, and the drop count is recorded (`dropped` field). This is the concrete mechanism for SUB-7 ("must not rewrite the underlying event") and SUB-6 ("keeps the violation undiscovered while obeying fixed case facts") — fabrication is structurally prevented, not just prompted away.
- **Typed, schema-validated turns with bounded repair** (`a2a.py:221-240`, `typed_turn`): `REPAIRS = 1` re-prompt on schema-validation failure, raw model "thinking" never read or recorded (only a short `reasoning_summary`, capped at 300 chars and itself subject to the same cite-or-drop check, `clean_reasoning` in `swarm.py:220-224`). Maps to AST-7 (schema-enforced flags) and SUB-7/EX-4 (no invented facts).
- **Self-framing prompt** (`swarm.py:266-277`, `Team._frame`): "This is a simulation... not a statement by {rival}. You know ONLY the evidence listed below... You cannot see other bidders and you have no tools... Never write a dollar sign... refer to an award by its number instead." This is the template the Arena's subject-persona system prompt should generalize (swap "evidence about the rival" for "private subject packet" and the financial-figure ban for a fact/violation ban).
- **Budget/call caps shared across all agents on one bus** (`swarm.py:63-67`, `SWARM_CAP_USD`/`SWARM_MAX_CALLS`; `a2a.py:188-190`, `Bus.admits`): a turn past the cap is `REJECTED`, never run — maps to BKO-8's "max output tokens, context limit and response budgets" and KPI-4 (3s/95th coaching latency — budget admission is instant/local, no network call when the bus is already spent).

**Confidence: high.** Code read directly; docstrings explicitly label the design rationale (`swarm.py:1-21`).

**Caveat:** TechnoMile's personas role-play *companies*, not truthful/deceptive *people*; there is no dedicated "truthful vs. deceptive" branch, no uncertainty-disclosure behavior (SUB-2), and no sealed per-turn disclosure tag (the deck's working-rule #5 in REQUIREMENTS.md ambiguity 5). The Arena must add: a role flag (truthful/deceptive) driving system-prompt branches, an uncertainty/disclosure policy per SCN-8, and a sealed ground-truth tag per turn for the fidelity judge — none of this exists in TechnoMile and would be new work, not a lift.

## 3. A2A protocol: A2A-shaped data model, no A2A transport

Grep for `a2a|A2A|AgentCard|agent_card|RemoteA2aAgent|to_a2a` across the repo (excluding node_modules, .venv) returns 44-47 files. The real design doc is `docs/research/swarm/A2A.md:1-31` and the implementation is `services/run/src/bh_run/tail/a2a.py:1-241`.

**Exact finding:** TechnoMile explicitly rejected ADK's native A2A (`to_a2a`, `RemoteA2aAgent`) and the `a2a-sdk` dependency. It built its own in-process `AgentCard` / `AgentMessage` / `Bus` using the A2A spec's *vocabulary* (agent id/name/role/skills, message parts, `messageId`/`contextId`/`taskId`, task states completed/failed/rejected) but an in-process bus instead of network transport (`A2A.md:16-27`): "A2A-shaped messages over an in-process bus, recorded to the run ledger... it keeps REQ-RUN-18 and the pins intact; it adds no server, port or deploy surface." Reasoning cited: REQ-RUN-18 forbids ADK orchestration/fan-out; a server-per-agent would add ~25 local ports per run; and ensemble research says gains come from independent sampling + aggregation, not cross-agent chatter, so messages are scoped per-rival/per-red-team only (`A2A.md:14`, citing "H6 section 2.2").

**Implication for the Arena:** the investigator-coach / subject-interview exchange is naturally two-party and turn-based (not a multi-agent swarm), so the case for real A2A transport is even weaker here than in TechnoMile. The same in-process `AgentCard`/`AgentMessage`/task-state pattern is directly liftable for the "agents visibly doing work" UI requirement (owner constraint) and for BKO-9's "commit findings before exposing labels" (task states let the UI show "coach: working" before a finding is committed).

**Confidence: high** (primary source read in full; no A2A server code found anywhere in the repo).

**`holdout_scoring` mechanism** (read in full, `.../migrations/20260928001100_holdout_scoring.sql:1-180` and its test `.../tests/011_holdout_scoring.sql:1-141`) — **the single most directly reusable isolation pattern for the Arena's sealed evaluator packets and hidden case families**:
- `ops.holdout_scorings`: one row per sealed case-list hash (`holdout_sha256` = primary key, sha256-shaped `check`), admitted exactly once, and only on/after a hard-coded cutover date (`admitted_at >= timestamptz '2026-10-27'` as a table `check` constraint — the "once, not before milestone M" rule is enforced by the database schema itself, not application code).
- `ops.holdout_case_admissions`: each sealed case id can be admitted (built) exactly once ever, via `ops.admit_holdout_case`, which refuses (`BH032`) a repeat or a case outside an open scoring.
- `ops.holdout_results`: one result row per admission (`primary key = holdout_sha256`), and a `completed` result is only accepted if (a) the admitted-case count equals the sealed `n_cases` and (b) the sha256 of the sorted, newline-joined admitted case ids equals the holdout's own seal hash — i.e. the database cryptographically proves every sealed case was actually run before it will accept a "complete" verdict (`record_holdout_result`, lines 119-153).
- Every table is append-only via a `tg_forbid_mutation()` trigger; RLS enabled; **everything revoked from `public, anon, authenticated, service_role, bh_api, bh_worker` by default**, then narrow `grant execute` given only to `bh_worker` on the four RPCs.
- The pgTAP test suite (32 assertions) proves: no back-dated admission, no double admission (same or different ranker), no admission before the cutover, no reading the raw tables directly (`42501` — insufficient privilege), no result without proof of full coverage, append-only enforcement, and that `service_role` specifically has no execute privilege on the admission function.

**Confidence: high** — both files read in full, including every constraint and every test assertion.

**Implication for the Arena:** replace "holdout" with "hidden evaluation case family" and "ranker_digest" with "scorer/candidate version digest" and this schema is close to a verbatim lift for SCN-12 (sealed hidden split, leakage audit) and BKO-9 (commit findings before exposing labels — the `record_holdout_result` proof-of-full-coverage check is exactly "commit before reveal"). The grants pattern (`20260927000700_grants.sql:1-30`: `authenticated` reads only via RLS, `service_role` gets nothing, two narrow service roles do everything else through RPCs) is the template for separating the "scorer/evaluator" role (reads SCN-9 packets) from the "assistant"/"subject" agent roles (must never read SCN-9).

## 11. Handoff — most relevant lessons and decisions

From `docs/handoff/LESSONS.md` and `DECISIONS.md` (full files read):
- **"Product lesson (gold run): summarizing is where citation accuracy dies"** (2026-09-25) — an independent re-fetch of a hand-built brief found only 58.8% of claims supported after summarization compressed qualifiers away; fix was "verify the final artifact, not just the research... forbid summarizers from merging claims whose evidence ids differ." Directly relevant to AST-7 (flags must cite an exact transcript turn) — any coaching-assistant summarization step must re-verify citations post-summary, not just at generation.
- **"A gate stated in an evaluation section is not enforced until the consumer's contract enforces it"** (2026-09-25) — a downstream component silently used a value whose use was supposed to be gated by an upstream eligibility flag, because the rule lived in prose, not in the consumer's code contract. Maps directly to EVL-10's eligibility gate (FPR ≤5% AND isolation/leakage pass, THEN rank) — the ranking code must structurally refuse to read recall/questioning-quality scores before the eligibility gate passes, not just document the order.
- **"Judgments are typed, rendered from templates"** (2026-09-27) — after 7 rounds of lexical-bypass findings on free-text parsing, the fix was typed output objects rendered through fixed display templates, with lexical checks only as a fail-closed backstop. Directly informs AST-8 (closed-category enum: non-responsive/contradiction/uncertainty/evasion) — enforce as a typed enum field, not prose classification.
- **"Tracing export is default-deny"** (2026-09-27) — iterative hardening across OBS cold rounds; informs the Arena's SCN-5/SCN-9 secrecy requirements if any subject/scorer internals ever touch telemetry.
- **"Allowlists over denylists for judgments and ICD display"** (2026-09-27) — supersedes an earlier "withhold on over-cap" design; shows the team converged on structural allowlisting over text-pattern denylisting, a pattern to prefer for AST-7's citation validation and EX-4's ground-rule enforcement.
- **"Fetch durability stays with the caller (REQ-SEC-04)"** (2026-09-27) — a stateless service (bh-fetch) must never gain its own Supabase/secret access just to solve a Cloud-Run-scale-to-zero durability problem; the caller persists instead. Directly reinforces the Arena's "simple architecture, no over-engineering" and scale-to-zero constraints: don't give the subject/assistant agent services their own DB credentials.
- **"Equal family exposure is not equal treatment in a winner calculation"** (2026-09-25) — a modulo rotation that looked balanced in marginal counts produced unequal outcomes under joint assignment; the fix required proving invariance with adversarial fake effects.
