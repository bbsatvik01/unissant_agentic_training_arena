# U4: Best-in-class references to emulate

Research date 2026-10-08. Scope: route U4 of the owner's UI/UX mandate — a curated, dated set of best-in-class product references (voice assistants, coaching/training apps, agent-activity views, leaderboards, motion-design award sites) to borrow *specific, named* visual and interaction moves from, plus the patterns and anti-patterns those references imply for our seven screens (interrogation room, coach card, evidence board, debrief, arena matrix, leaderboard, trust center).

**Non-repeat boundary.** `X5` (external) already covers interrogation/detective-game mechanics, "agents visibly working" prior art, avatar/pet/voice design rules and ethics in depth — read it first, this route does not re-derive it. `I7` (internal) already inventories the gokbase "kin" pet system and TechnoMile's agent-at-work motion as liftable code — not repeated here. Sibling routes in this same batch (`U1` tools/pipeline, `U2` avatars/pets/voice techniques, `U3` motion libraries/jargon-free copy) are visible in this directory; this route is the only one built specifically around *named, dated product references* and the borrow-list those references produce, so it stays at that altitude rather than re-litigating library choices (`U1`/`U3`) or avatar-tech comparisons (`U2`). No final decisions are made; colors and fonts are explicitly out of scope pending the owner's DESIGN.md.

**Constraints carried forward (from `02-direction.md` §0, 2, 3, 6, 9 and the sponsor requirements):** PRB-4 — no stress/nervousness meters; avatar demeanor and voice are independent of role; nervousness is never evidence. EX-4 — the synthetic-only ground rule must stay visible in onboarding, the room, debriefs, leaderboards and methodology. Assessment mode hides coaching mid-session. Reduced-motion support and WCAG 2.2 AA throughout. §3.3's cut order (pets, agents-at-work animation and Live Avatar are first-cut, never-cut keeps the 9N metrics, isolation, fairness and EX-4) means every pattern below is framed as an enhancement layer over a working, accessible baseline, not a dependency for it.

## 2. Concrete patterns for our seven screens

1. **Single-state-machine voice indicator, mirrored 1:1 from the API.** Don't invent "thinking/speaking/listening" states independently — map them directly from `interaction_status`/`turnComplete`/`interrupted` (ref 3) so the UI can never show a state the backend isn't actually in. *Interrogation room.*
2. **Barge-in cuts the animation, not just the audio.** The instant `interrupted: true` arrives, the speaking animation must stop in the same frame the audio buffer is discarded — a half-second lag where the mouth keeps moving after audio stops is the single most "uncanny" failure mode voice UIs hit (ref 3, ref 1). *Interrogation room.*
3. **Keep the room visible during voice.** A pill/bar overlay (ref 2) beats a full-screen voice takeover — the investigator needs the evidence board and transcript on-screen while talking, which this arena's "voice is relay-only, development cases only" scope (§9 of `02-direction.md`) makes especially important since voice sessions are the exception, not the default mode.
4. **Scenario briefing happens before the session starts, not during it.** A persona/topic/stakes card shown once at entry (ref 16, ref 6) — not a settings panel reachable mid-interrogation — keeps the live screen free of configuration chrome.
5. **Three-state turn delivery for the coach card: skeleton → streaming → done.** Varied-width skeleton bars, fade handoff, no layout shift when the full card (flags/follow-up/finding/confidence per §6.1) lands (ref 20).
6. **Name the job, not the technology, in every label.** "Your coach for this interview" / "What changed since the last answer" — never "AI assistant," "AI-powered," "powered by AI" (ref 17 is a directly citable 2026 trend statement for this). Directly serves the owner's no-jargon mandate.
7. **Evidence release as three explicit, visually distinct states.** Pending → validated → released (borrowing the allowlist→sandbox→judge vocabulary of ref 13), rendered as distinct badges/positions on the evidence board rather than one generic spinner — this also happens to map cleanly onto the backend's real privileged-function lifecycle (`02-direction.md` §4), so the UI state and the system state are the same state, not a fiction layered on top.
8. **Side-panel, not modal, for anything the investigator consults while working.** Evidence board detail, coach explanations and the trust-center note should all live in a persistent panel (ref 11) rather than blocking dialogs, so the main interrogation never pauses to dismiss something.
9. **Replay dial + running checklist for "agents at work."** A compact widget showing what step a background agent (subject turn processing, referee scoring) is on, with a scrub control once the run is finished (ref 12, ref 14) — this is explicitly first-cut-first per §3.3, so build the checklist text/data model now even if the animated scrub control ships later.
10. **Leaderboard rows carry an interval, never a bare rank.** A visible spread/band per entry (ref 7), with overlapping intervals rendered as a tie rather than a false ordering — this is not a design nicety, it is required by P5 (honest statistics) in `02-direction.md` §2.
11. **Animated rank-change via re-callable scale transitions, with an explicit reduced-motion escape hatch.** `axis.transition()`-style tweening (ref 21) for the normal case; `interrupt()` on every in-flight transition when `prefers-reduced-motion` is set, jumping straight to the end state rather than disabling the leaderboard's re-sort logic.
12. **Status-grouped rows, not recency-sorted rows, for any multi-trial overview.** "Needs attention" and "ready to review" float to the top (ref 10) for a judge or exhibition view across many concurrent trials — directly useful for KPI-5/observability and for the Oct 27-30 reveal window in the schedule.
13. **Debrief as a scrubbable moment, not only a static scorecard.** Let the five 0-4 cards (§6.1/§7) link into a replay position (ref 14) so "why was this turn scored a 2" is one click from the transcript, not a separate lookup.
14. **Trust-center/EX-4 badge: persistent and small everywhere, restated with new words at the moments that matter.** A small always-visible synthetic-content indicator (ref 19) avoids the interstitial-everyone-dismisses problem, but the *habituation* finding in the same research means the onboarding, debrief and leaderboard copies should each say it slightly differently (not the identical sentence three times) so it doesn't fade into wallpaper exactly where EX-4 needs it to land.

(14 patterns; floor was 10-15.)

## 3. Anti-patterns — "AI slop," named and checkable

Per ref 24 (the Hallmark catalogue) and ref 18/20's corroborating sources, the checkable tells to gate against before any screen ships:

- **Purple-to-blue gradient on white/dark** as a background or card treatment — identified as the single most statistically common, most recognizable "AI product" fingerprint. Whatever palette DESIGN.md lands on, it should not be this by default.
- **`box-shadow` glow on everything** (cards, buttons, avatars) as a default treatment rather than a sparing emphasis device — this is the Hallmark catalogue's literal example pattern.
- **Sparkle icons (✨) and "Live"/"New" badges used as decoration** rather than to convey a real, checkable state — ties directly into "no AI jargon": a sparkle icon is the visual equivalent of the word "AI-powered."
- **Robot/android avatar iconography for the coach.** Beyond generic-AI-slop, this specifically risks PRB-4: a robot face reads as "the machine is judging you," re-introducing the demeanor-as-evidence problem through imagery instead of a meter. The coach's visual language should read as a tool with a job (ref 17), not a face passing judgment.
- **Generic particle backgrounds and hero sections built from a copy-paste template** (centered headline, three rounded cards, Inter font, gradient signature) — explicitly called out as "losing favor" in 2026 motion-design circles (ref 18, low confidence on specifics but directionally consistent with ref 24).
- **Stress/anxiety-coded color or motion on any avatar** — pulsing red, shaking, a reddening "heat" effect tied to assessed veracity. This is the UI-design restatement of PRB-4's hard requirement that demeanor is never evidence; it applies to *accidental* visual signaling (an avatar that "looks nervous" when flagged) just as much as to an explicit meter.
- **A single, one-time disclosure interstitial for EX-4** that the investigator dismisses once and never sees again — the disclosure-fatigue research (ref 19) says a static, never-repeated warning is worse than a small persistent one, because it creates a false sense that disclosure "already happened."
- **Borrowing landing-page bravado at the component level** — a shader-driven hero animation or scroll-jacked narrative (the literal Awwwards/Godly aesthetic in ref 18) belongs on a marketing site, not inside a working interrogation room; it actively fights the reduced-motion and "clean, not loud" mandate when applied to a tool people use repeatedly under time pressure.
- **Mascot creep** — letting the coach pet acquire a persistent, chatty personality that shows up on every screen regardless of relevance, the exact overreach Microsoft pulled Mico back from in 2026 (ref 4). Scope the pet to the screens where it is doing a job (coach card, loading states), not a permanent fixture.

## 5. Contradictions / tensions (not resolved here)

- **"Scoped, narrow-job AI agent" framing (ref 17) vs. "companion pet with a face and personality" framing (refs 4, 6, 15).** The no-jargon mandate pulls toward naming a job and staying invisible-as-infrastructure; the "pets like ChatGPT/Copilot/Duolingo" mandate pulls toward a character people recognize and warm to. Both are real 2025-2026 trends running in parallel in the references above, not a solved tension — the owner's DESIGN.md will need to pick how much "face" the coach gets without it reading as mascot creep (anti-pattern, §3) or drifting into PRB-4 territory if that face is ever allowed to look "worried" about the subject's answers.
- **Award-site motion bravado (ref 18) vs. clean/calm/WCAG-AA product motion (owner mandate, §3 anti-patterns).** The brief literally asks for "amazing, stunning" animation *and* "clean" *and* reduced-motion support — these pull in different directions at the extremes, and the references here resolve it only at the trend level ("2026 SOTD winners show restraint"), not with a worked example inside a working tool rather than a marketing site.
- **Persistent trust-center badge (ref 19, pattern 14) vs. disclosure-fatigue research from the same reference.** The same source that recommends a small persistent badge also warns that any *unchanging* signal gets ignored — so "always visible" and "actually noticed" are not the same design goal, and no reference here shows a worked solution to both at once inside a single product.
