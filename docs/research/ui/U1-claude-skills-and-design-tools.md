## 5. Contradictions / tensions

1. **Three overlapping "anti-slop" skills (`frontend-design`, `design-taste-frontend`, `impeccable`) are each independently confident in their own cliché-ban list and process**, and none defers to the others. Running more than one on the same surface risks the agent getting contradictory micro-guidance (e.g., two different "don't do this font pairing" rules) rather than compounding benefit — pick one primary skill per surface (§3 step 2), not all three.
2. **Stitch is fast, prompt-driven, static-screen-oriented tooling; the arena's hardest UI problems (agents visibly at work, speaking avatars, companion pets) are event-driven state machines, not static screens** — I7 already found zero Rive/Lottie/3D/canvas dependency in either reference codebase it surveyed, and this route's Stitch research did not surface any Stitch capability for behavior/state-machine generation (it generates HTML/CSS screens and variants, not FSMs or animation-timing logic). The generation tooling in §2.2/§3 step 1 is a good fit for static/form-heavy surfaces and a poor fit for the state-machine-driven surfaces, which should continue to be hand-built per I7's lift map.

## 6. Implications for the arena build

- The project already has two well-matched, installed local skills (`impeccable` for product UI, `design-taste-frontend` if a marketing surface ships) and one high-value, zero-cost, not-yet-installed option (Anthropic's own `frontend-design` plugin, already cached locally in the `claude-plugins-official` marketplace) — no new marketplace or network install is needed to get all three onto this project; `frontend-design` just needs `claude plugin add anthropic/frontend-design` run with the owner's go-ahead.
