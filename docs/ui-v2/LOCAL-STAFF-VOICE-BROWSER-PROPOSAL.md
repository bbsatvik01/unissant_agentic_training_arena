## Assertions and cleanup scenarios

- Before click: no staff source created, no WAV fetched, closed mouth, dialog Canvas demand.
- Actual play: finite exact subtitle/manifest/response bytes and SHA agree; native context is running, source is started, graph reaches destination, decoded PCM is nonzero, post-gain live PCM varies, and actual face morphs vary over at least two active samples. Dialog body stays stationary; Canvas becomes always only for permitted, unmuted local speech.
- Mute: gain becomes zero, mouth closes immediately on a final invalidated existing frame, Canvas returns to demand while the dialog stays open. Native graph data may need several output quanta/FFT windows to drain; bound the wait and report the measured settle time. An ended clip is not evidence of mute. Unmute within an ongoing clip reattaches actual output and resumes mouth/frame activity.
- Stop, natural end, close panel, replace reply, and leave route: active handle finishes, source is stopped or ended, context closes, analyser ownership detaches, no late speech occurs, and the mouth closes. After panel close, normal exploration may legitimately set Canvas to always; only expect demand while the dialog/inactive or paused scene is otherwise static.
- Pause via real UI: the native modal blocks the outside Pause button. Press Escape to dismiss the modal (which must stop speech), then focus Canvas and press Escape again to pause exploration. Verify cleanup before and during the pause. Do not claim a direct mid-speech `paused=true` browser transition if this UI cannot produce it. The existing focused unit tests cover the direct paused prop gating. If a future genuine UI enables pause with a dialog still open, add that separate browser scenario.
- Reduced motion: enable it through actual settings, reopen staff and explicitly play. Real audio can play; speech morphs stay zero and no extra speech-only frame loop runs. Restore only in the disposable test context.
- Replay: use the actual separate recording flow when available; no live crowd/body mouth or staff audio is regenerated from body-only samples. A read-only scene inspection alone cannot prove a full replay flow.
- Failure/cancellation: in a dedicated fault-test context intercept only the finite local WAV request to delay, 404 or alter one byte, then use real play/stop/close controls. These deliberately faulted responses must be labeled test fixtures and never counted as genuine asset playback. Record that late completion does not start output. Existing unit tests cover decode and ownership failure seams; retain those tests.
- One speaker: real dialog line replacement stops the first clip before a second explicit play. The separate installed-device control shares an ownership event, but browser speech synthesis must only be allowed in an explicitly separate local test if that arbitration path is exercised.
- Microphone: staff tests must observe zero acquisition attempts. The acquisition-failure regression is currently unit-mocked. Any future actual microphone test needs its own bounded grant on our test browser; never silently access the user's microphone.
